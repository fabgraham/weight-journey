# Changes — 24 October 2026

## 1. Secret rotation and the "Unauthorized" error

After the Railway security incident, the project's variables were rotated. The live
app then showed **Unauthorized** on every screen.

- **Cause:** the API rejects any request whose `x-api-key` header does not exactly
  match Railway's `API_SECRET` (`apps/api/src/middleware/auth.ts`). The frontend
  and the local `apps/api/.env` still had the same key, but Railway's `API_SECRET`
  was different.
- **Fix:** a single new secret was generated (`openssl rand -hex 32`) and set in
  all three places:
  1. Railway → API service → Variables → `API_SECRET` (then **Deploy**, because
     Railway only applies variable changes on deploy).
  2. Vercel → Environment Variables → `EXPO_PUBLIC_API_SECRET`, then a redeploy
     **without build cache**. `EXPO_PUBLIC_*` values are compiled into the bundle
     at build time.
  3. Local `apps/api/.env` → `API_SECRET`.
- **Check:** `curl -H "x-api-key: <secret>" https://weight-journey-production.up.railway.app/weight`
  returns data, not 401.

## 2. Dashboard: quick weight logging

Previously, logging a weight meant clicking **Log weight**, filling in a separate
form and saving. You can now log it directly on the dashboard.

- New **Log weight** card (`apps/app/src/features/weight/components/QuickLogWeight.tsx`):
  - **DATE** field, defaulting to today, with the same calendar picker as the full
    form. Future dates cannot be picked.
  - **WEIGHT (KG)** field. Its placeholder shows the last logged weight
    (e.g. `64.7`).
  - The button reads **Log weight** while the field is empty; clicking it puts the
    cursor in the weight field. Once a weight is typed, the button reads **Save**
    and saves the entry without leaving the page. Pressing Enter also saves.
  - Validation matches the full form: 30–300 kg, no future dates.
  - If an entry already exists for that date, you are asked whether to overwrite
    it.
  - After saving, the field clears, the date goes back to today, a confirmation
    appears, and the chart and list refresh.
  - Layout: date, weight and button in one row on desktop (≥ 640px), stacked on
    phones.
- The overwrite prompt moved to `apps/app/src/features/weight/confirmOverwrite.ts`,
  so the dashboard card and the full log form share it.
- `DateField` gained an optional `fieldClassName` prop, so a card can give the date
  field a white background. Existing screens are unchanged.
- The full log form (tapping an entry in the list) is still used for editing and
  deleting entries.

## 3. Dashboard layout and styling

- Order: **Weight History** stats → **Log weight** → **Ask about your weight
  history** → range tabs, trend chart and entries.
- The "Log weight" and "Ask about your weight history" headings sit above their
  cards, in the same style as "Weight History".
- The stat tiles, Log weight card and Ask card all use the same background
  (`#f8f5ef`). The stat tiles were slightly lighter before (`#faf8f3`).
- The **Goal** tile was removed, leaving a 2×2 grid: Start weight, Current, Your
  BMI, Days on journey. The 70 kg goal line on the Trend chart was kept on
  purpose.
- The **Ask** button is always enabled. Pressing it with an empty question does
  nothing.
- New **1Y** chart range (the last 12 months, counted back from the latest entry,
  like the other ranges). Range labels are now capitalised: **All, 1M, 3M, 6M,
  1Y**. On phones the five range buttons share the row equally so they all fit;
  from 640px wide they keep their natural spacing.
- New **Year ▾** dropdown after 1Y (`apps/app/src/features/weight/components/RangeTabs.tsx`).
  It lists every year that has an entry, newest first, so new years appear
  automatically. Picking a year shows January to December of that year: the
  button shows the year (e.g. **2025 ▾**), the chart heading reads "2025 ·
  January to December", and the list shows that year's entries (12 at a time,
  with "Show all"). Choosing any other range switches back. The menu closes when
  you pick a year, tap the button again or choose another range; clicking
  elsewhere does not close it.

## 4. Bug fix: "today" in the full log form

The full log form worked out today's date in UTC, so during UK summer time it
showed yesterday's date between midnight and 1am. It now uses the local date
(`apps/app/app/(tabs)/log.tsx`).

## 5. Repository clean-up

- **Database password removed** from `RAILWAY_HANDOVER.md` and replaced with a
  placeholder. The old password is still in git history, and the repository is
  public, so the Railway Postgres password must be reset (if it hasn't been
  already).
- **`supabase/` folder removed:**
  - `schema.sql` is plain Postgres and is still the only definition of the
    database tables, so it moved to `apps/api/db/schema.sql`. The API README now
    explains how to apply it. References in `RAILWAY_HANDOVER.md`,
    `RAILWAY_MIGRATION.md` and `IMPLEMENTATION_CHECKLIST.md` were updated.
  - `seed.sql` and `generate-seed-sql.mjs` were deleted. They were only used to
    load the data into Supabase once; the data now lives in Railway Postgres (with
    local backups in `backups/`, which git ignores).
- `.gitignore` now excludes `backups/`.
